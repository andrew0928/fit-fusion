# 本機 FIT 依出發日期查詢，按原始內容匯出

## 狀態

`accepted`。2026-11-25 使用者檢視依日匯出、按 ID 讀取、跨午夜歸屬及整月批次的操作案例後，確認進行 M4-2。

## 背景

使用者希望只指定目錄和日期，就能從不同設備的歷史 FIT 挑出活動。車錶檔案可能改名、複製或出現在子目錄，且騎乘可能跨午夜。

## 決策

`fit-query-files` 提供獨立的 `list`、`read`、`export`。活動按 FIT 內的出發時間及查詢時區歸日；期間包含起日、排除迄日。活動 ID 沿用原始位元組的 SHA-256，設備依 FIT 內容識別。按日或期間匯出原始位元組，重跑核對既有副本；遇同名異內容時保留既有檔並回報該筆衝突。[已實作的命令契約](../spec/m4-cli.md#本機-fit-目錄)

## 影響

原始 FIT 始終唯讀。查詢與檢查器共用 Rust 的 FIT 解析邏輯，每支執行檔可離線獨立使用。單元與端對端測試沿用 Garmin SDK 樣本，另用本機 10 月跨午夜及 11 月三趟實騎核對日期、匯出內容與重跑結果。

## 替代方案

曾有以舊合併器的個人設定及具名資料來源開啟本機目錄的流程。M4 讓使用者直接指定目錄；agent 可以把清單回傳的活動 ID 帶入下一個操作。[M4 工具邊界](2026-11-25-independent-pair-merge.md)

## 後續工作

M4-3 將相同的查詢操作套用至 Garmin Connect。其穩定 ID 與原生檔取得方式由 Garmin 來源規格定義。
