# 合併前雙檔評估列為 agent 可選用的 skill 主題

## 狀態

`accepted`。2026-11-26 使用者指定保留雙檔合併行為，並以獨立 skill 引導 agent 在合併前提醒騎士留意共同欄位的差異。

## 背景

兩台裝置可能都有心率或總熱量，實際記錄卻有長缺口、重複值或明顯的數值差距。只列出兩檔都有哪些欄位，無法判斷換來源的效果。

## 決策

`fit-merge --skill preflight` 指引 agent 用 `fit-inspector` 讀取兩個來源，在可比時段比較覆蓋率及實值，回報來源、差異、選用後果與不確定性。騎士指定的欄位決定最終的合併命令。[操作指引](../../src/rust/pair-merge/guides/preflight.md)

同日使用者確認，公開指引可以保留實測數字與判讀情境，來源以主檔、附檔說明，省略個別騎乘的地點、人物與設備。英文版若需引用中文專有名詞，英文名稱後以括號附中文原文。[共通寫法](../spec/cli-common.md)

## 影響

評估期間只讀來源。直接執行合併時沿用原有的參數與選欄行為。拿到單一執行檔的 agent 也可以從索引讀到比對步驟。

## 替代方案

在合併時自動呼叫檢查器或切換來源會改變明確選欄的契約。使用者選擇將判讀交給操作工具的 agent。[雙檔覆寫決策](2026-11-25-independent-pair-merge.md)
