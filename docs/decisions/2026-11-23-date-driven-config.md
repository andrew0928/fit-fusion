# 個人設定檔分開定義來源與逐串流順位，依日期從主來源找活動

## 狀態

accepted。2026-11-23 使用者審閱設定範例與日期配對規則後回覆「config OK」，確認 v1 作為 M2 的實作依據。[設定檔規格](../config/README.md)

## 背景

原先 M2 草案的設定檔僅包含 profile 名稱與平台授權，仍需在命令列提供車表檔名。相同的 CIRQA 記錄可從 Connect 或本機備份取得，心率和熱量的優先順序應能沿用。

## 決策

採用有版本的 JSON。`sources.<id>` 定義設備、取檔方式、路徑及需要的憑證。`merge.primary_source` 決定活動發現與主時間軸，`merge.streams` 明列要輸出的同名欄位及其來源 ID 順位。日期依設定時區的主活動出發日，對每趟活動分別在其他來源配對。[完整範例](../config/config.example.json) · [機讀契約](../config/config-v1.schema.json)

## 影響

Garmin 可在 API 與本機目錄間切換，兩種方式共用同一個來源 ID。同日多趟各自有合併結果，跨午夜只歸出發日。Apple 健康匯出保留為分析來源。Strava 的發佈授權獨立置於同檔的目的地區段。

## 替代方案

每次提供雙檔便於單趟診斷與離線重播，沿用為輔助入口。只提供 profile 名稱會讓使用者難以看出實際選了哪些串流，也無法直接編輯順位。

## 後續工作

2026-11-24 M2-3 已完成六趟正式 Garmin API 與離線雙檔對照，以及同日多趟、分頁、跨午夜、候選衝突、來源晚到與重跑驗收。逐趟發佈排在 M2-4。後續以其他騎乘持續驗證 0.90 門檻。[日期處理契約](../config/README.md#只給日期時的處理契約) · [M2-3 驗收](../spec/testcases/merger.md#m2-3-日期與-garmin-實測)
