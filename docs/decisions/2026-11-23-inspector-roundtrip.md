# 三種檢查器以解碼後的欄位重新編碼 FIT

## 狀態

accepted。2026-11-23 使用者指定先增加 Rust 檢查器，並以解析、序列化及讀回驗證新 FIT。使用者驗收後再開始 M2 合併器開發。

## 背景

既有 `raw` 可從 frame 的 `hex` 還原原檔 SHA-256，仍需另外驗證解碼器對欄位型別、數值、developer index 與時間戳的解讀能否寫回可用的 FIT。

## 決策

Python、C# 與 Rust 各提供 `roundtrip FILE --out NEW.fit`。前兩者使用各自的 wire 解碼器與編碼器。Rust 用 RustyFIT 0.11.2 解出訊息模型並交給其 Encoder，以獨立 Rust wire reader 驗證寫出結果。Rust 的盤點也可比較 SDK 樣本值與獨立 wire 樣本值，兩者依 wire 定義取欄位寬度。三語言共用名稱與單位表。

判定以逐 member、逐訊息、逐欄位的讀回結果為準。允許 local definition 排程、大小端、時間戳壓縮方式及字串尾端填充改變，另報檔案 SHA-256 是否相同。原生與 developer 同號欄位分開比較，保留數值精度、陣列、無效值與未知欄位。SDK 遺失原欄位或值時，回傳錯誤且不交付該輸出。

## 影響

來源唯讀，目的須為新的路徑。跨語言驗收由另一個讀取器開啟各份輸出。使用者可以留存新 FIT、比對結果與雜湊。[操作與重現](../inspectors.md#三種檢查器的-fit-往返驗證)

## 替代方案

直接拼接原始 frame 適合驗證無損封存。單看 CRC 或資料筆數無法識別合法 FIT 裡被改寫的心率、私有欄位或 developer index。

## 後續工作

2026-11-23 使用者確認接受實檔逐值相等、位元組可有差異的驗收結果，開始 M2 離線雙檔合併。M2 合併器另依其保存規格處理原始位元組與選源。Node.js 檢查器仍待實作。[合併器規格](../spec/merger.md)
