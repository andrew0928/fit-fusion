# CLI 依預先定義的裝置與資訊流對照表選取來源

## 狀態

accepted（產品方向）。2026-11-22 使用者要求未來能一次提供同一趟運動的檔案，讓 CLI 依預設對照表辨識裝置並選取數值來源。設定檔格式與合併實作留待後續里程碑。

## 背景

FIT 的 `file_id.manufacturer` 由 Garmin 配發，`file_id.product` 由各廠商編定，故型號須使用兩者的組合查詢。Apple Health 原生 XML 有自己的裝置識別欄位。[Garmin Activity File 規格](https://developer.garmin.com/fit/file-types/activity)

## 決策

預設對照須能回答兩個問題：

1. 這份輸入是哪一種記錄裝置？已知 FIT 使用製造商與產品編號配對。目前樣本包含 Garmin `(1, 5019)` 與 Bryton `(267, 2205)`。前者有官方 CIRQA 對照；後者的 Rider 460 名稱來自使用者提供的樣本背景。原生 Apple Health 運動使用 Workout 的裝置資料，本次硬體代碼為 `Watch7,1`。
2. 此裝置的哪個欄位可提供所需指標？例如已辨識為 Bryton 的活動，其心率取自 `record.heart_rate`；來源優先順序沿用[既定決策](2026-11-22-bryton-primary-streams.md)與[資訊流對照表](../specification.md)。

## 影響

已知裝置可重複套用設定，檔案更名或輸入順序改變均不影響識別。來源須區分檔案建立者、運動記錄裝置與外接感測器。此批 Bryton 檔案可辨識車表；使用者事後確認當天車表接收 CIRQA 廣播。[本趟來源更正](2026-11-22-nov21-heart-rate-repair.md)

## 替代方案

每趟手動指定裝置或依檔名辨識，都需要使用者重複維護資訊。單以產品編號比對則可能發生跨廠牌碰撞。

## 後續工作

定義可機讀的設定格式、未知裝置與轉檔來源的處理方式。以檔案改名及打亂輸入順序驗證，並在合併報告標明各資訊流實際使用的裝置、來源欄位與選用規則。
