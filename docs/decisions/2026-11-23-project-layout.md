# 專案以 docs、src、data 與 runtime 分開保存文件、程式及本機資料

## 狀態

accepted。2026-11-23 使用者指定將 repository 整理為專案，文件、規格、研究與決策集中於 `docs/`，所有開發原始碼集中於 `src/`，另區分執行產物與資料。

## 背景

Python 套件、C# 專案、測試和比對腳本原本各在根目錄。首頁主要描述第一階段的檢查器，較難找到融合 CLI 的規格及里程碑。

## 決策

根目錄 README 作為專案入口。`docs/` 存放規格、里程碑、研究、操作說明與決策。`src/python/` 與 `src/csharp/` 存放各語言實作與相關測試，`src/tools/` 放跨語言工具。`data/` 存放私人來源及校驗清單，`runtime/` 放建置結果、虛擬環境及比對報告。[專案目錄](../../README.md)

## 影響

Python 與 C# 仍共用一份 FIT Profile。根目錄的 `CONTEXT.md` 導向文件區的里程碑與資料保存要求。執行產物與個人活動資料在本機保留，Git 僅追蹤專案內容。

## 替代方案

各語言與工具在根目錄各自成區容易找到單一實作，跨語言驗證與文件則分散在多個入口。

## 後續工作

正式 Rust CLI 開發時在 `src/` 下建立其專案。加入新工具時一併確認輸入為唯讀、輸出路徑與驗證指令。[檢查器使用說明](../inspectors.md)
