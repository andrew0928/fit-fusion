# M4 依用途拆分 CLI，移轉 M3 並結束 Strava API 上傳計畫

## 狀態

**同日後續修訂。** 下文保存首稿。來源拆分、M3 移轉及手動上傳 Strava 仍適用；合併器角色、開發順序與退場時程以[獨立雙檔覆寫決策](2026-11-25-independent-pair-merge.md)為準。

`accepted`（方向與範圍）。2026-11-25 使用者指定保留兩支現有 CLI、新增四支，廢除 M3 和 M2-4。任務切分、介面與驗收草案仍待使用者確認。[M4 開發計畫](../milestones/m4-cli.md)

## 背景

v0.1.0 的日常入口把活動搜尋、Garmin 取檔、配對、合併與輸出組合起來。騎士也需要單獨查詢來源，或將已選好的多個本機 FIT 交給同一套規則處理。

## 決策

- 保留 `fit-inspector` 的唯讀檢測與 `fit-fusion` 的既有規則合併。新增 `fit-merge` 做顯式多檔合併，新增 `fit-query-files`、`fit-query-apple`、`fit-query-garmin` 分別查詢、讀取及匯出本機 FIT、Apple Health 匯出檔與 Garmin Connect 活動。
- [原 M3](2026-11-23-cli-milestones.md) 廢除，憑證、發佈、整合及跨欄映射的責任分派至 M4 具體項目。原有 M1、M2 已交付的功能與 v0.1.0 發版紀錄保留。
- M2-4 廢除，取代[先前暫緩的決定](2026-11-24-manual-strava-export.md)。使用者從本機選取合併 FIT 手動上傳 Strava，沒有對應的後繼自動上傳項目。

## 影響

六支 CLI 各有明確用途。既有選源、心率品質、熱量、原檔保存與離線檢查是重構的回歸基準。曾規劃的 Strava OAuth、上傳、輪詢、判重及 API 實機驗收從開發排程移除。舊設定仍可讀。

## 替代方案

v0.1.0 集中提供日期探索與合併入口，日常操作只需一條命令。M4 保留這種用法，同時讓已經備好檔案或只想查詢資料的使用者能單獨操作。
