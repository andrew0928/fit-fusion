# 0.2.x 開發獨立 CLI，先交付無設定檔的雙檔覆寫

## 狀態

`accepted`。2026-11-25 使用者指定 M4 從 0.2.0 開始、0.3.0 起讓 `fit-fusion` 退場，確認允許功能重複及 Apple 的逐趟轉製 FIT 方案。本決策取代[原 M4 拆分方向](2026-11-25-cli-split.md)中維持兩個合併入口協作、以來源角色合併多檔及沿用來源備援的部分。

## 背景

舊 CLI 將設備、存取位置、順位與合併規則集中在設定檔。已拿到兩份 FIT、知道要換哪個欄位時，檔案路徑和欄名就足以表達意圖。

## 決策

- 0.2.x 主目標為新 CLI。第一個開發任務是 `fit-merge`，每次只接受主 FIT、附加 FIT、明列的覆寫 stream 與輸出路徑，完全透過命令列運作。更多檔案由使用者以上一次輸出為下一次主檔分次處理。
- 所選串流整條取自附加檔，缺口保留為缺值。使用者確認附檔整檔缺欄即報錯並保留既有檔案；有欄位定義但全部失效時，仍輸出所選欄的缺值。缺樣分析由 `fit-inspector` 提供，回報有效取樣、缺樣數與缺樣率，供使用者決定覆寫欄位。
- 查檔、Apple Health 匯出 ZIP 與 Garmin Connect 由各自的 query CLI 處理。Apple 按 Workout 另存標明來源的轉製 FIT，保留原始採樣與缺項。
- 新工具可重用移出的程式碼與相同套件，執行及驗收皆獨立於 `fit-fusion`。0.3.0 起舊 CLI 進入退場階段。

## 影響

0.1.0 的品質切換、優先順位、Garmin 自動選源與 config v1 作為舊版紀錄保存。新合併器只依這次明列的欄位覆寫。正式發佈前可單獨安裝和測試每支新工具。

## 替代方案

首稿曾規劃多個來源 ID、共用 config、逐點備援及串接舊 CLI。使用者選擇以雙檔角色、欄位名稱及分次執行簡化操作。

## 後續工作

M4-1 以實際 CLI 參數、稀疏附檔與連續兩次合併驗收。時間對齊、整檔缺欄及統計分母的具體提案見[CLI 規格](../spec/m4-cli.md)與[驗收表](../spec/testcases/m4-cli.md)。
