# M2 以設定行為與唯讀活動來源切分模組

## 狀態

accepted（模組邊界、介面簽名與驗收條件）。2026-11-24 騎士以 C# 草圖提出兩個模組，確認邊界後要求補上 Rust 對照。同日審閱規格後指示「commit, 標記模組介面確認」，採用此版規格作為 M2 實作依據。[設定與活動來源介面](../spec/config-and-data-source.md)

## 背景

依日期合併需要先找主活動，再從其他來源取得同趟紀錄。Garmin 的同一份活動可由本機或 Connect 取得；心率又可能因後段資料停滯而整趟換源。取檔方式與跨來源的品質判定各有不同的變更原因。

## 決策

設定模組載入既有 config v1，提供主來源、啟用欄位、各欄位的來源順位、目的地及整趟合併策略。來源模組封裝活動列舉、指定 ID 的 metadata 與唯讀活動記錄。M2 以編譯時註冊擴充來源。合併器從已配對的記錄產生一次選值結果，FIT 和報告共用其中的值與來源證據。[設定檔 v1 決策](2026-11-23-date-driven-config.md)

## 影響

呼叫端可在相同來源 ID 下更換取檔實作，或用同一組原檔驗證策略變更。既有串流順位、熱量原值保存與品質待判讀行為依逐欄規格執行。[合併器規格](../spec/merger.md)

## 替代方案

全域 `GetSources()` 排序無法同時表達心率與總熱量的不同順位。以時間點直接呼叫 `GetData<T>()` 則需要在 getter 內掃描整趟，才能正確處理 11/21 的前段心率。採整趟選值讓判定時機與來源在呼叫端可見。

## 後續工作

實作時沿用雙檔回放做對照，補上替換來源、離線列舉設定與日期候選的模組驗收。具體案例集中在[介面規格的驗收邊界](../spec/config-and-data-source.md#驗收邊界)。
