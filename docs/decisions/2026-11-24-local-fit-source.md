# 資料來源依取檔方式分型，第一個實作為本機 FIT 目錄

## 狀態

accepted。2026-11-24 騎士指定本機 FIT、Garmin API、Apple Health 匯出 ZIP 分別建模，本次先完成本機 FIT 來源。四張決策表的整體結構已確認，可按表實作與驗證。

## 背景

Rider 460 與 CIRQA 都能提供本機 FIT。兩者可共用讀取器，依設備身分及設定的來源 ID 區分。Apple 匯出雖然也是本機檔案，其活動發現與內容解讀方式需要專屬讀取器。

## 決策

第一個連線器為 `fit_directory`。遞迴列舉一般檔案，接受大小寫 FIT 副檔名，從 FIT 讀取設備與騎乘時段。以內容 SHA-256 作為活動 ID。讀到同一份複本只列一次，開啟後各欄位共用同一份解碼資料。手動雙檔沿用此讀取器與合併策略。另保留 `garmin_connect` 與 `apple_health_export` 的獨立類型。

## 影響

載入設定可離線列舉已宣告來源。第一版僅在本機保留本次列舉的記憶體索引，每次重新列舉均檢查目錄內容和 CRC。資料來源有錯時回報失敗及路徑，以免把部分結果當成完整的一天。檔名可自由更換，來源 FIT 一律唯讀。

## 替代方案

以品牌區分連線器會重複實作 FIT 讀檔。以檔名識別活動則會在改名後失去對應，也容易錯認重複複製的活動。

## 後續工作

依日期從本機來源發現並配對同一趟活動，核對六趟基準，再實作 Garmin API 讀取。Apple 匯出繼續供分析使用。[可執行案例](../../README.md#驗證本機-fit-目錄來源)
